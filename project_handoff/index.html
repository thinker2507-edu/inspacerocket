01 / FIRST USE

Start with the right vehicle

Ground control

  1. Open workswithoutcmd copy.html in Chrome/Edge.
  2. Connect the USB LoRa receiver at115200 baud.
  3. Choose Rocket/CanSat under Control. Both telemetry streams stay visible; commands address one board.
  4. Click Telemetry ON and wait for the selected flight ACK.

Mission workflow

Keep stationary, calibrate, set UTC if needed, ARM and wait. Mission elapsed starts at detected launch, not boot. Rocket recording must be stopped before ARM; start recording after arming.

Manual servos are available at any phase. One request at a time. An ACK never proves physical deployment or recording.

REMOTE COUNTER RESET / SELECT ONE VEHICLE FIRST
TELEM OFF              → wait for ACK
RESETCOUNT CONFIRM     → wait for durable DONE
TELEM ON              → first new packet1, new epoch

RESETCOUNT preserves mission/logs/calibration; it is not flash erase. Number ranges are reserved before transmitting; ordinary reboot gaps prevent reuse.

02 / POLICY

PAD-only gates removed.
Execution checks retained.

Available beyond PAD

Telemetry OFF, calibration requests, RTC setting, reboot, camera start after landing and confirmed mission reset no longer fail just because of flight phase. Active ARM is idempotent: it reports the active mission instead of resetting it. Manual servos already bypass phase/sensor/storage gates.

Failures are still honest

Address/key/checksum/argument validation, sensor freshness/stillness, busy transactions, hardware failures, storage integrity and compile-mode restrictions remain. A valid command cannot invent sensor samples or a committed flash write.

Operator consequences: CAL BARO/ACCEL can change reference/filter. RESETPAD CONFIRM explicitly clears flight detection and automatic-action state even airborne. TIME changes UTC; REBOOT interrupts software. Removing the phase gate does not remove the physical consequence.

Flash recovery, logging and factory erase

NOR stores sparse mission/recovery/calibration/events/counter checkpoints. Rocket built-in SD stores normal CSV samples. CanSat has no SD, so there is no full-rate flight CSV log there. Recovery reads bounded4KiB slices, validates records and never erases on ordinary boot. Torn/foreign/full/missing storage can prevent durable numbering or automatic intent. Invalid reset time continuity is flagged, not invented.

CanSat direct USB ERASEFLASH CONFIRM is first60s only, with explicit unarmed/idle/telemetryOFF safeguards. It deletes ALL8MiB history, verifies every byte and reboots. It stays USB-only. STATUS FLASH is read-only; do not factory-erase an unknown active mission.

05 / FAILURE GUIDE

A timeout is not a rejection

Before execution

GCS blocks, invalid bridge frames or RF losses may produce no flight ACK. Check selected vehicle, serial connection, receiver uplink output and matching channel. CanSat responding does not prove the rocket link.

After acceptance

OK may mean queued. Asynchronous commands can later return DONE/FAIL. Only matching valid ACKs confirm a request. A timeout means unknown outcome; no automatic retry is sent.

GCS will not send

Disconnected/no writable port; replay active; request pending; wrong selected vehicle; malformed name/argument/raw envelope/key/checksum/sequence; frame>99bytes; unsupported receiver channel. One flight request at a time.

Receiver discards or waits

LF-terminated addressed $CMD needed. CR/control/non-ASCII, invalid identity/checksum/fields, >99bytes or partial line>1s discarded. Waits for addressed RX window or1200ms fallback; incoming RF header may defer. Radio TX/RX API errors are not execution success.

Firmware silent validation drops

Requires $CMD, canonical decimal team:R/C,4or5 commas with no empty fields, printable non-space ASCII, no embedded $/*, final*HH/XOR, correct vehicle/team and decimal32-bit sequence. RF CRC/read errors, TX/not-listening or pending ACK can prevent receipt.

Authentication / duplicates

Wrong key can ACK AUTH_KEY. Same latest sequence repeats cached ACK without action. Older remembered duplicate ACKs DELAYED_DUPLICATE. A pending ACK serializes reception.

Real execution failures

Invalid arguments/ranges, absent hardware, stale/unreliable IMU, motion/pressure instability, insufficient samples, bad/foreign/full flash, failed write/readback, busy operations, exhausted IDs/counters, unsupported MCU/disabled feature. PAD-only gates are removed, not these facts.

Async completion

CAL, RADIO, camera persistence, RESETPAD, RESETCOUNT can accept then DONE/FAIL. OK need not mean completed. Timeout/lost ACK means unknown outcome; no automatic retries.

GCS rejects a reply or packet

Wrong/corrupt/unmatched/late ACK address/checksum/status/sequence cannot confirm request. Telemetry additionally rejects invalid16-field schema/source/state/epoch, unknown address and duplicate/delayed counters. Telemetry rejection differs from command rejection.

USB erase failures

Window closed; attempt locked; unsafe/non-idle maintenance state; absent/wrong/busy/protected chip or WEL refusal;120s timeout; read failure/non-FF verification. Correct JEDEC is not a valid journal.

Physical delivery failures

Wrong frequency/SF/sync, antenna/power/wiring, RF collision, reboot or hardware fault can lose request/reply. A CanSat ACK does not establish the rocket link. Timeout is not a NACK or proof of a particular physical cause.
